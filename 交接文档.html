对象：要接手这套自动化的同学 · 目标机器：一台全新的 Mac（或已在另一台机器上重新克隆）
范围：app-automation/ 全部三层（接口 / 单元 / 视觉）
写于 2026-11-25
接手前先看这一节，30 秒判断现在能不能跑。
这套东西的代码是完整的，但当前测试账号不可用（.env 里的 QA_USERNAME=pss2 登录报「账号或密码错误」）。换到新机器后，你把账号填对，才能跑通视觉层。另外有 4 项修复改完还没在真机上验证过， 详见 第 8 节。除此之外，接口层、单元层、门禁测试不依赖账号，可以立刻跑。

1. 它是什么

一套跑在真机上的 App 自动化测试，覆盖三层：

层跑在哪测什么条数
接口pytest + requests登录、鉴权、任务接口的返回结构6
单元jest（App 自己的 src/__tests__）纯函数：上传队列、进度计算、QC 指标14
视觉Midscene.js + adb，驱动真机界面流程：登录、引导、采集、QC、上传40（23 手写 + 17 源码派生）

另外有 2 条由其他用例覆盖、4 条只能人工、1 条等版本，合计对应测试设计清单里的 50 条用例。 50 是设计清单的条数，视觉层实际执行 40 条，两者不是一回事，看报告时别混。

一条命令 ./go.sh 跑完三层，合并成一份 HTML 报告。

2. 转移清单：带什么，不带什么

这个目录没有被 git 跟踪。在仓库根执行 git ls-files app-automation 是空的， 所以不能靠 git clone 带走，必须整个目录拷贝。下面的排除项要在拷贝时手动去掉。

必须带走

路径内容
app-automation/ 下除下列排除项之外的全部三层源码、用例、脚本、文档。.py 约 5700 行，.ts 约 5400 行
core/ tests/ pages/ verification/ apis/ config/ utils/ tools/ reporting/接口层与门禁
vision/src/ vision/cases/ vision/package.json视觉层三层架构与全部用例
go.sh setup.sh install_app.sh三个入口脚本，拷贝后要 chmod +x
*.md（含 自动化排障手册.md、vision/README.md）排障方法与设计说明，比代码更值钱
screenshots/ 里的基线图（不含 current/）视觉回归的对照基准

绝对不要带走（体积 + 安全）

排除项体积原因 / 到新机器怎么办
.env、vision/.env小含生产账号密码和模型 key。新机器重建，见第 4 节
.venv/60 MB虚拟环境的解释器路径是绝对路径，换机器必坏。新机器重建
vision/node_modules/195 MB含平台原生二进制（esbuild）。跨平台拷过去会直接报错
../node_modules/（仓库根）2.2 GB同上，jest 依赖。新机器 npm install
vision/midscene_run/1.4 GB全是截图和录屏，含测试账号与密码输入过程。只可内部使用，永不外发
reports/ evidence/ screenshots/current/20 MB历史产物，新机器会重新生成

一个可直接用的拷贝命令（在仓库根执行，按需改目标路径）：

rsync -av --progress \
  --exclude '.venv' --exclude '__pycache__' --exclude '*.pyc' \
  --exclude '.pytest_cache' --exclude '.env' \
  --exclude 'node_modules' \
  --exclude 'midscene_run' --exclude 'reports' --exclude 'evidence' \
  --exclude 'screenshots/current' \
  ~/mono-capture/app-automation/  /目标路径/app-automation/

3. 新机器从零搭起来

3.1 前置条件

依赖版本说明
macOS—脚本用 bash 3.2 写的，macOS 自带即可，不需要装新版 bash
Python≥ 3.9系统自带 3.9 就能用
Node≥ 18视觉层和 jest 都要
Android platform-tools—adb 要在 PATH 里
安卓真机Android 10+开发者选项 + USB 调试打开，首次连接要在手机上点「允许」
被测安装包.apk包名 com.apex.collect，问项目负责人要

3.2 五步搭起来

第一步 · 拷贝
按第 2 节的清单把目录拷过去，然后恢复脚本权限（拷贝常常会丢）：

cd /目标路径/app-automation
chmod +x go.sh setup.sh install_app.sh
ls -l go.sh          # 要能看到 -rwx，看不到就会报 permission denied

第二步 · 建两个 .env
app-automation/.env 抄自 .env.example，vision/.env 抄自 vision/.env.example。 每一项的含义见第 4 节。账号和密码只写在本地，不要提交、不要贴群里。

第三步 · 装依赖

./setup.sh          # 建 .venv、装 python 依赖、装两处 node_modules
./setup.sh --check-only   # 只检查不安装，随时可用

第四步 · 接设备、装包

adb devices                                   # 看到设备号且状态是 device
./install_app.sh ~/Downloads/ApexCollect-x.x.x.apk
./install_app.sh --all ~/path/app.apk         # 多台都装

第五步 · 先跑不碰设备的部分

./go.sh --quick      # 单元 + 门禁 + 接口，几十秒，不需要真机，不花钱
这一步全绿，说明环境、依赖、配置都对了，再去碰真机。真机那层要花时间和模型费用，别拿它当第一次验证。

4. 配置项说明

只需要两个文件。下面不写具体值——值属于项目，向负责人要。

app-automation/.env

键作用
QA_USERNAME / QA_PASSWORD测试账号。视觉层的登录、接口层的鉴权都用它。视觉层会自动映射成 EGO_USERNAME / EGO_PASSWORD
ANDROID_UDID设备序列号。换设备必改，否则脚本拦下来报「配置里的设备不在线」
ANDROID_APP_PACKAGE包名，默认 com.apex.collect
QA_API_BASE接口层用的后端地址
QA_MAIN_SITE_HOST / QA_SERVER_ID登录用的主站与服务器档位（新/旧服务器）
QA_VIDEO_*、QA_QC_*、QA_GOLDEN_*产物校验和黄金链路的参数（分辨率、QC 选项、录制时长）

vision/.env

键作用
MIDSCENE_MODEL_BASE_URL模型中转地址，要带 /v1
MIDSCENE_MODEL_API_KEY模型 key，按次计费
MIDSCENE_MODEL_NAME / MIDSCENE_MODEL_FAMILY模型名与家族，两个要配套
EGO_USERNAME / EGO_PASSWORD可留空，留空就自动用 QA_USERNAME
MIDSCENE_ANDROID_DEVICE_ID可留空，留空就用 ANDROID_UDID
空字符串不等于没设置。vision/.env 里写 MIDSCENE_RUN_DIR="" 会让 Midscene 直接抛 「run directory must be a non-empty path」——它只判断变量存不存在，不看内容。代码里已经把空的 MIDSCENE_* 删掉了， 但你自己加新变量时注意别留空串。

6. 日常怎么跑

./go.sh                        # 全部：代码层 + 视觉层（真机，40 分钟以上）
./go.sh --quick                # 只跑代码层，几十秒，不碰设备
./go.sh --check                # 只检查环境，不跑用例
./go.sh --apk app.apk          # 先装包再跑
./go.sh --device <序列号>       # 多台在线时指定跑哪台
./go.sh --review               # 新项目接入：从源码派生冒烟用例 + 生成审核页
./go.sh --import-review f.json # 把审核结果写回用例

视觉层单独跑（可以开自愈，go.sh 里为了控总时长是关掉的）：

cd vision
npx tsx src/cli.ts --all                    # 全部，卡住自动修，最多 3 轮
npx tsx src/cli.ts --cases AUTH-01 --no-heal    # 只跑一条，不修
npx tsx src/cli.ts --tier smoke             # 只跑冒烟档
npx tsx src/cli.ts --dry-run                # 只看计划，不碰设备
npx tsx src/cli.ts --list                   # 列用例和顺序档位

报告在哪

路径内容
vision/midscene_run/reports/all-latest.html合并报告，看这个。三层并成一张表，带审核状态
vision/midscene_run/reports/latest.html只有视觉层，含失败截图和录屏
vision/midscene_run/last-run.json视觉层的结构化结果，下游只认这个
vision/midscene_run/logs/各层完整日志，出事时先翻这里
带媒体的报告只可内部使用。截图和录屏里有测试账号和密码的输入过程， midscene_run/ 整个目录永远不要外发、不要提交、不要传到任何云端。

直接带走，一行不用改

三层骨架（plan.ts / run.ts / heal.ts / patch.ts）、 报告生成、控件树工具、审核流程、源码派生、执行顺序规则、统一入口 run_all.py、三个 shell 脚本、 以及 自动化排障手册.md。约 3300 行。

接入新项目的最小流程： ① 填 .env ② 写 appContext.ts / prepare.ts ③ npx tsx src/cli.ts --derive 从源码派生结构性冒烟 ④ --review-page 生成审核页，人逐条过一遍 ⑤ --import-review 写回 ⑥ 再跑全量。
人只负责「什么算对」，机器负责摆状态、按顺序跑、取证、归因、出报告。

8. 已知问题与未验证项

这一节比上面都重要。交接时不说清楚，接手的人会把「没验过」当成「跑通了」。

事项状态说明
测试账号不可用 阻塞 QA_USERNAME=pss2 登录报「账号或密码错误」，上一轮 4 条用例因此失败。必须换成可用账号才能跑视觉层
check-all 修复 改完未验 上一版把整屏 61 个节点当复选框挨个点，把界面点进了协议文档页和「视频已失效」。已改成只认 checkable="true"，还没上真机
门禁 4 条失败 改完未验 3 条是审核门禁的 check() 参数传错，1 条是自愈写入白名单漏了 htmlPath。已改，跑 pytest -m gate 可验
报告生成崩溃 已修 run_all.py 在「通过的用例」上取 splitlines()[0] 越界，导致视觉层跑完、报告写不出去。同时加了「开跑前删掉上次残留结果」，避免没跑成却显示旧数据
AUTH-04 会锁账号 设计如此 连续错 5 次锁 15 分钟。用同一个账号跑全量，跑完账号就锁了。建议给它单独配一个账号，或跑全量时排除这条
派生用例的深链 部分失效 /earnings、/projects、/done 用深链打开后仍停在首页，tab 路由没切过去。/home、/login、/local-packages 是好的
jest 10 条失败 待查 3 个套件 10 条失败，报错在 src/collectionUpload.ts:255「交付包数据不完整」。属于 App 自身的单测，与自动化框架无关，但会一直红
登录前置超时 待查 有 4 条报「等待登录页超时」，但现场描述是「当前为登录页面」，自相矛盾。怀疑是更新弹窗遮挡导致判断失败
40 条用例全部「未审核」 正常 报告顶部会写「N/M 条没过人工审核」。审核流程跑一遍就会消失
一条设计红线，交接时务必守住：执行层（run.ts）里不要加任何判断逻辑—— 不要「先读控件树再决定要不要问模型」这类优化。曾经试过，被明确否掉：那本质是把守卫层装回去， 上一版正因为守卫层让 8 条用例烧了 195 次模型调用。要降成本只能动用例层、模型选择、或者整轮之外的调度。

9. 换机器一定会再踩的坑

现象原因怎么办
./go.sh: permission denied拷贝丢了可执行位chmod +x go.sh setup.sh install_app.sh，或临时用 bash go.sh
esbuild 报「installed for another platform」node_modules 跨平台拷贝删 vision/node_modules 和 package-lock.json 重装。这是打包目录时最容易犯的错
mapfile: command not foundmacOS 自带 bash 3.2脚本里已改用字符串处理，别改回去
脚本变量变成乱码$var 后面紧跟全角括号，bash 会把括号当变量名写 ${var}
账号输进去了只剩最后一个字输入法把按键收进候选区，只有最后一次提交落进输入框已设 imeStrategy: 'always-yadb' 绕开输入法；输入后要读回核对。别改回默认策略
pm clear 后所有按钮点不动清数据连带清了运行时权限清完立刻补权限，代码里已做成成对操作
用例顺序一改就集体失败前一条的副作用带给了后一条policy.yaml 里 order 是必填的（normal / costly / destructive），漏写会在加载阶段直接报错
换设备后视觉层起不来ANDROID_UDID 还是旧机器改 .env，或跑 ./go.sh --device 新序列号
报告里的数字对不上50 是设计清单，视觉层实际 40 条看报告副标题，会写清楚这一轮哪些层跑了
